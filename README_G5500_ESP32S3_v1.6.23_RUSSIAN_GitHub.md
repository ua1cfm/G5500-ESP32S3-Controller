# Контроллер YAESU G-5500 на ESP32-S3 — прошивка v1.6.23 DIAG PC TIME

**Автор:** UA1CFM  
**Контроллер:** ESP32-S3-DevKitC-1 N16R8  
**Дисплей:** 2.4" 240×320 TFT, ILI9341  
**Контроллер тачскрина:** XPT2046  
**Bluetooth:** внешний модуль HC-05 Bluetooth Classic  
**Прошивка:** `G5500_ESP32S3_Controller_v1_6_23_DIAG_PC_TIME.ino`

---

## 1. Назначение проекта

Эта прошивка превращает ESP32-S3 в сетевой, USB- и Bluetooth-контроллер
антенного поворотного устройства YAESU G-5500.

Контроллер поддерживает:

- обратную связь положения AZ / EL;
- независимое движение по AZ и EL;
- одновременное движение AZ + EL;
- команды в стиле Yaesu GS-232 / GS-232B;
- управление из PSTROTATOR через USB Serial;
- управление из Look4Sat / Hamlib через TCP;
- команды GS-232B через внешний модуль Bluetooth Classic HC-05;
- встроенную точку доступа Wi-Fi;
- подключение к домашней сети Wi-Fi;
- Web-интерфейс состояния и ручного управления;
- Web-калибровку;
- TFT-панель состояния;
- сенсорное управление XPT2046 и калибровку тачскрина;
- режимы азимута 360° и 450°;
- две независимые системы калибровки:
  - двухточечную GS-232;
  - многоточечную кусочно-линейную;
- отдельные данные калибровки AZ для P36 и P45;
- общую калибровку EL;
- диагностику ADC;
- историю RSSI Wi-Fi;
- историю перезапусков;
- Web Diag Console;
- временные метки локального времени компьютера в Web Diag Console.

Версия v1.6.23 является стабильной TFT-базой до экспериментальных работ
по плавному старту и плавному торможению двигателя.

## 2. Важная информация по безопасности

GPIO ESP32-S3 **нельзя подключать напрямую к силовым цепям двигателей G-5500**.

Четыре управляющих GPIO должны работать через оптопары либо через другой
подходящий согласующий/развязывающий интерфейс. Транзисторная сторона оптопары
замыкает соответствующую управляющую линию YAESU на линию COMMON G-5500.

Напряжение обратной связи G-5500 также необходимо понизить до безопасного
для ADC ESP32 уровня перед подачей на GPIO4 или GPIO5.

Перед подключением поворотки:

1. проверьте нумерацию контактов DIN-8;
2. помните, что со стороны пайки разъём выглядит зеркально относительно вида спереди;
3. мультиметром проверьте все четыре управляющих выхода;
4. убедитесь, что напряжение на входах ADC не превышает допустимого для ESP32-S3;
5. отдельно проверьте LEFT / RIGHT / UP / DOWN перед включением автоматического сопровождения.

## 3. Распиновка ESP32-S3

### 3.1 Обратная связь положения

| Функция | ESP32-S3 |
|---|---:|
| Обратная связь AZ | GPIO4 |
| Обратная связь EL | GPIO5 |

В прошивке:

```cpp
static const int PIN_AZ_ADC=4;
static const int PIN_EL_ADC=5;
```

ADC работает в 12-битном режиме с ослаблением 11 dB. Для измерения положения
используется `analogReadMilliVolts()` с усреднением по 25 отсчётам.

---

### 3.2 Выходы управления повороткой

| Функция | ESP32-S3 |
|---|---:|
| LEFT | GPIO15 |
| RIGHT | GPIO16 |
| UP | GPIO17 |
| DOWN | GPIO18 |

В прошивке:

```cpp
static const int PIN_LEFT=15;
static const int PIN_RIGHT=16;
static const int PIN_UP=17;
static const int PIN_DOWN=18;
```

Эта распиновка принципиально важна. Она совпадает с распиновкой,
использовавшейся в более ранней LCD-ветке контроллера на ESP32-S3.

Правильная цепочка:

```text
GPIO15 -> LEFT  -> G-5500 DIN pin 4
GPIO16 -> RIGHT -> G-5500 DIN pin 2
GPIO17 -> UP    -> G-5500 DIN pin 3
GPIO18 -> DOWN  -> G-5500 DIN pin 5
```

Не перепутайте RIGHT с UP, а LEFT с DOWN.

## 4. Разъём внешнего управления YAESU G-5500

Прошивка рассчитана на следующее назначение контактов:

| Контакт DIN-8 G-5500 | Функция |
|---:|---|
| 1 | обратная связь EL |
| 2 | RIGHT |
| 3 | UP |
| 4 | LEFT |
| 5 | DOWN |
| 6 | обратная связь AZ |
| 7 | данным контроллером не используется |
| 8 | COMMON / GND |

Движение включается замыканием соответствующей управляющей линии
на контакт 8 (COMMON).

### Рекомендуемое подключение оптопар

Для каждого направления используется отдельная оптопара.

Сторона ESP32:

```text
ESP32 GPIO
   |
  330 Ом
   |
PC817 pin 1 (A)
PC817 pin 2 (K) -> GND_SYS
```

Сторона G-5500:

```text
PC817 pin 4 (Collector) -> соответствующая управляющая линия G-5500
PC817 pin 3 (Emitter)   -> G-5500 COMMON, DIN pin 8
```

Четыре канала:

```text
GPIO15 -> PC817 -> LEFT  -> DIN pin 4
GPIO16 -> PC817 -> RIGHT -> DIN pin 2
GPIO17 -> PC817 -> UP    -> DIN pin 3
GPIO18 -> PC817 -> DOWN  -> DIN pin 5
```

## 5. Подключение TFT-дисплея с тачскрином

Прошивка рассчитана на TFT ILI9341 и резистивный тачскрин XPT2046,
работающие на общей SPI-шине.

На использованном при разработке модуле контакты подписаны так:

```text
GND VCC CLK MOSI RES DC BLK MISO CS1 CS2 PEN
```

### 5.1 Подключение TFT / Touch

| Контакт дисплея | ESP32-S3 | Назначение |
|---|---|---|
| GND | GND | общий провод |
| VCC | 3.3 V | питание дисплея |
| CLK | GPIO11 | SPI SCK |
| MOSI | GPIO10 | SPI MOSI |
| RES | GPIO14 | Reset TFT |
| DC | GPIO13 | Data/Command TFT |
| BLK | 3.3 V | подсветка |
| MISO | GPIO2 | SPI MISO |
| CS1 | GPIO12 | Chip Select TFT |
| CS2 | GPIO8 | Chip Select XPT2046 |
| PEN | GPIO9 | прерывание Touch |

Определения в прошивке:

```cpp
static const int PIN_TFT_MOSI=10;
static const int PIN_TFT_SCK =11;
static const int PIN_TFT_MISO=2;
static const int PIN_TFT_CS  =12;
static const int PIN_TFT_DC  =13;
static const int PIN_TFT_RST =14;

static const int PIN_TOUCH_CS =8;
static const int PIN_TOUCH_IRQ=9;
```

Общая SPI-шина:

```text
MOSI -> GPIO10
SCK  -> GPIO11
MISO -> GPIO2
```

Отдельные линии выбора устройств:

```text
TFT CS     -> GPIO12
TOUCH CS   -> GPIO8
TOUCH IRQ  -> GPIO9
```

### 5.2 Ориентация дисплея

В прошивке используется:

```cpp
tft.setRotation(1);
touch.setRotation(1);
```

Эта ориентация соответствует физическому расположению TFT
в данном контроллере.

### 5.3 Белый экран во время прошивки

Белый экран TFT во время загрузки прошивки в ESP32-S3 является нормальным.
Во время USB-прошивки пользовательская программа ещё не выполняется,
поэтому она не может инициализировать ILI9341 и вывести рабочую панель.

После Reset и запуска прошивки TFT инициализируется и показывает стартовый экран.

## 7. Калибровка тачскрина

XPT2046 имеет собственную сохранённую калибровку.

Если допустимые данные калибровки отсутствуют, прошивка автоматически
запускает четырёхточечную raw-калибровку тачскрина при старте.

Калибровочные данные сохраняются в Preferences / NVS ESP32
и не теряются после обычной перезагрузки.

Для повторного запуска калибровки можно удерживать палец на основной
TFT-панели примерно **2,5 секунды**.

Если после замены дисплея, его поворота или замены контроллера Touch
координаты касаний неверны, сначала выполните повторную калибровку.

## 8. Меню калибровки поворотки на TFT

С TFT можно перейти к функциям калибровки ротатора.

В прошивке реализованы два алгоритма.

### GS-232 2-POINT

Калибровка AZ хранится раздельно для двух диапазонов:

```text
P36: 0° ... 360°
P45: 0° ... 450°
```

Калибровка EL общая:

```text
0° ... 180°
```

Команды GS-232:

```text
O   = текущая обратная связь AZ соответствует 0°
F   = текущая обратная связь AZ соответствует полной шкале:
      360° в P36
      450° в P45

O2  = текущая обратная связь EL соответствует 0°
F2  = текущая обратная связь EL соответствует 180°
```

### MULTI-POINT

Точки AZ для P36:

```text
0°
90°
180°
270°
360°
```

Точки AZ для P45:

```text
0°
90°
180°
270°
360°
450°
```

Точки EL:

```text
0°
45°
90°
135°
180°
```

Наборы калибровки сохраняются независимо в NVS.

## 9. Модуль Bluetooth Classic HC-05

ESP32-S3 не предоставляет встроенный Bluetooth Classic SPP,
используемый этим проектом, поэтому в v1.6.23 применяется
**внешний модуль HC-05**, подключённый к UART1.

### 9.1 Сигнальное подключение HC-05

| HC-05 | ESP32-S3 |
|---|---|
| STATE | GPIO3 |
| TXD | GPIO6 |
| RXD | GPIO7 |
| GND | GND_SYS |
| EN / KEY | для обычной работы не требуется |

Параметры UART:

```text
9600 baud
8 data bits
No parity
1 stop bit
```

Определения в прошивке:

```cpp
static const int PIN_HC05_STATE=3;
static const int PIN_HC05_RX=6;
static const int PIN_HC05_TX=7;
static const uint32_t HC05_BAUD=9600;
```

Инициализация:

```cpp
HC05Serial.begin(HC05_BAUD, SERIAL_8N1, PIN_HC05_RX, PIN_HC05_TX);
```

TX и RX подключаются крест-накрест:

```text
HC-05 TXD -> ESP32 GPIO6  (ESP RX)
HC-05 RXD <- ESP32 GPIO7  (ESP TX)
```

### 9.2 Питание HC-05

Напряжение питания зависит от конкретной платы HC-05.

Многие распространённые breakout-модули HC-05 имеют встроенный стабилизатор
и обычно питаются от 5 В, при этом сам Bluetooth-модуль является устройством
с логикой 3,3 В. Перед подключением питания обязательно проверьте маркировку
и схему именно вашей платы HC-05.

Логические сигналы ESP32-S3 имеют уровень 3,3 В.

### 9.3 Вывод STATE

Прошивка читает:

```cpp
digitalRead(PIN_HC05_STATE)
```

Высокий уровень трактуется как установленное Bluetooth-соединение.

Поэтому на TFT и в Web-интерфейсе можно отображать состояние:

```text
CONNECTED
```

или:

```text
DISCONNECTED
```

### 9.4 Обработка команд Bluetooth

Команды GS-232, принятые через HC-05, поступают в тот же парсер,
что и команды GS-232 через USB.

Ответ возвращается в тот интерфейс, из которого пришла команда.

Например, запрос `C2`, полученный через HC-05, получает ответ также через HC-05.

Это позволяет управлять повороткой со смартфона, планшета или другого
Bluetooth Serial-клиента без изменения набора команд.

## 11. Поддерживаемые команды GS-232

Прошивка реализует основные команды, необходимые для этого контроллера.

### Движение

```text
R   вращение RIGHT
L   вращение LEFT
U   движение UP
D   движение DOWN

A   остановить AZ
E   остановить EL
S   остановить всё
```

### Запрос положения

```text
C   прочитать AZ
B   прочитать EL
C2  прочитать AZ + EL
```

Примеры ответов:

```text
AZ=123
```

```text
EL=045
```

```text
AZ=123 EL=045
```

### Команды задания координаты

Только азимут:

```text
Maaa
```

Пример:

```text
M180
```

Азимут + элевация:

```text
Waaa eee
```

Пример:

```text
W180 045
```

### Диапазон азимута

```text
P36  -> 0...360°
P45  -> 0...450°
```

При смене P36/P45 движение AZ останавливается, а старая цель AZ отменяется,
чтобы она не использовалась после переключения диапазона.

### Калибровка

```text
O
F
O2
F2
```

### Справка

```text
H
H2
H3
```

### Важно

Команда `Z` в этой прошивке **намеренно не реализована**.

## 12. Алгоритм автоматического движения

Алгоритм наведения использует принцип, близкий к LVBTrack,
принятый в этом проекте.

При поступлении новой цели:

```text
AZ target > current AZ -> RIGHT
AZ target < current AZ -> LEFT

EL target > current EL -> UP
EL target < current EL -> DOWN
```

Оси работают независимо.

Поэтому возможны одновременные состояния:

```text
UP + RIGHT
UP + LEFT
DOWN + RIGHT
DOWN + LEFT
```

Когда цель достигнута или пересечена, соответствующая ось останавливается.

До получения первой корректной цели автоматического движения нет.

Ручная команда по одной оси отменяет автоматическое сопровождение
только для этой оси. Вторая ось может продолжать движение.

В v1.6.23 **нет** экспериментального PWM-профиля плавного старта
и плавного торможения силовой части двигателя.

## 13. Wi-Fi

Контроллер поднимает собственную точку доступа.

SSID по умолчанию:

```text
G5500-Rotator
```

По умолчанию пароль точки доступа пустой, поэтому AP остаётся открытой,
пока пароль не будет задан через Web-интерфейс.

В Web-интерфейсе можно сохранить пароль:

```text
8 ... 63 символа
```

Также можно сохранить SSID и пароль домашней сети Wi-Fi.

После успешного подключения к домашнему роутеру контроллер становится
доступен в локальной сети, при этом собственная точка доступа контроллера
продолжает работать в соответствии с сетевой логикой прошивки.

## 16. Web Diag Console

В v1.6.23 реализован диагностический RAM-лог.

Адрес диагностического журнала:

```text
/diaglog
```

RAM-лог является кольцевым буфером примерно на 160 строк.

Web-браузер добавляет к новым строкам журнала **локальное время компьютера**.

Пример:

```text
[16:14:22.381] | GS232 RX: W123 045
[16:14:22.405] | AZ -> RIGHT
```

Формат времени:

```text
HH:MM:SS.mmm
```

Важно: эта временная метка создаётся JavaScript-кодом браузера.
Она соответствует времени компьютера/браузера, когда строка была впервые
получена. Это не аппаратная временная метка ESP32.

Очистка диагностического RAM-лога также очищает локальный список
временных меток в браузере.

## 17. RGB-индикация состояния

Прошивка использует встроенный адресный RGB-светодиод платы,
если он доступен.

Резервный GPIO по умолчанию:

```text
GPIO48
```

Индикация:

```text
GREEN = получена управляющая команда / RX
RED   = отправлен ответ / TX
BLUE  = короткий heartbeat примерно раз в 2 секунды
```

Индикация неблокирующая.

## 21. Проверка распиновки после перехода с LCD на TFT

Переход на TFT-дисплей **не меняет** четыре GPIO управления повороткой.

Правильная распиновка остаётся:

```text
LEFT  = GPIO15
RIGHT = GPIO16
UP    = GPIO17
DOWN  = GPIO18
```

Если после перехода получилось:

```text
UP вместо RIGHT
RIGHT вместо UP
```

или:

```text
DOWN вместо LEFT
LEFT вместо DOWN
```

ошибка находится в проводке или распайке разъёма, а не в назначении TFT GPIO.

Сам TFT использует:

```text
GPIO2
GPIO8
GPIO9
GPIO10
GPIO11
GPIO12
GPIO13
GPIO14
```

и не использует GPIO15...GPIO18.

## 22. Диагностика неисправностей

### TFT остаётся белым после обычной загрузки

Проверьте:

```text
VCC  -> 3.3 V
GND  -> GND
CLK  -> GPIO11
MOSI -> GPIO10
RES  -> GPIO14
DC   -> GPIO13
CS1  -> GPIO12
```

Также убедитесь, что библиотека ILI9341 установлена.

Белый экран **именно во время прошивки** является нормальным.

### Тачскрин работает неправильно

Проверьте:

```text
MISO -> GPIO2
CS2  -> GPIO8
PEN  -> GPIO9
```

После этого запустите калибровку Touch ещё раз.

### HC-05 ничего не принимает

Проверьте:

```text
HC-05 TXD -> GPIO6
HC-05 RXD <- GPIO7
baud      -> 9600
GND       -> общий логический GND
```

TX и RX должны быть подключены крест-накрест.

### Bluetooth всегда показывает DISCONNECTED

Убедитесь, что ваша плата HC-05 действительно имеет рабочий выход `STATE`
и он подключён к:

```text
GPIO3
```

На некоторых вариантах HC-05 статусный вывод может иметь другую маркировку
или особенности работы.

### При RIGHT включается UP

Правильно:

```text
GPIO16 -> RIGHT -> DIN 2
GPIO17 -> UP    -> DIN 3
```

Проверьте выходы оптопар и ориентацию DIN-разъёма.

### При LEFT включается DOWN

Правильно:

```text
GPIO15 -> LEFT -> DIN 4
GPIO18 -> DOWN -> DIN 5
```

Особенно внимательно проверьте зеркальность DIN-разъёма со стороны пайки.
